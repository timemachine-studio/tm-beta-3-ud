# Raycast.com Landing Page — Full Design & UX Specification

Extracted directly from a screen recording of raycast.com, frame by frame. This is written so a build agent can implement it section by section without guessing.

---

## 0. Global Design System

**Theme:** Pure dark mode. Background is near-black, `#050505` to `#0A0A0A`, never flat pure `#000` (there's always a subtle vignette or gradient glow behind content).

**Primary accent color:** A saturated crimson/red, roughly `#FF3B30` to `#E8384A` range, used for the brand logo, hero background, and highlight accents throughout.

**Secondary accent colors:** Used only inside feature-showcase cards to differentiate them, cycling through blue (`#3B82F6`-ish), green/emerald (Spotify card), purple/magenta (Color Picker card), teal (TinyPNG card). The rest of the site stays monochrome red/white/gray.

**Typography:**
- Headlines: bold, tight-tracking geometric sans-serif (Inter/system-ui style). Large sizes: hero headline ~56 to 64px, section headlines ~28 to 34px.
- Body/subhead text: same sans-serif, regular weight, muted gray (`#9CA3AF`-ish), smaller size (~16 to 18px), usually two lines max, centered under a bold headline in "statement" sections.
- Monospace font used exclusively in the developer/API section (labels like `FIG_02`, `ACTION BAR`, `SEARCH BAR`) and in some code-adjacent UI captions. Looks like a technical-drawing annotation font.
- Standard paragraph text (nav links, footer links, card body copy): regular weight, white or gray depending on hierarchy.

**Buttons:**
- Primary button: white/off-white rounded-pill or rounded-rectangle background, black text, small icon on the left (a 4-square grid icon representing the Raycast app icon), e.g. "Download", "Download for Windows".
- Secondary/ghost button: transparent background, thin light-gray border, white text, e.g. "The Raycast Keyboard →".
- All buttons have visible hover states (slight brightness/scale change) and rounded corners (~8 to 10px radius).

**Cards:** Rounded corners (~12 to 16px), thin 1px semi-transparent border (`rgba(255,255,255,0.08)`-ish), dark fill slightly lighter than page background, occasional colored gradient fill for feature-showcase cards.

**Texture:** A grain/noise texture overlay is visible across the hero's red graphic and other colored sections, giving it a slightly gritty, film-grain look rather than a flat smooth gradient. This is a recurring brand signature.

**Layout grid:** Centered content column, max-width roughly 1200 to 1300px, generous vertical whitespace between sections (200px+), full-bleed backgrounds behind some sections.

**Motion language (site-wide):**
- Elements fade in and slide up (~20 to 30px) on scroll into view, staggered slightly between siblings.
- Section transitions often blur/dim the previous section as the next one becomes active (used heavily in the pinned/scroll-jacked demo section, see Section 2).
- Hover states on nav links: subtle background pill highlight.
- Cursor-following or scroll-linked reveal effects appear multiple times (typing text animations, streaming AI text, card carousels).

## 2. Hero Section

It looks like colored light beams or fabric folds, dark red fading to near-black at the edges of the viewport.

**Content (vertically centered, fades/slides in on load):**
1. Headline, two lines, extra bold, centered: **"Your shortcut to everything."**
2. Subheadline directly below, centered, smaller, light gray: **"A collection of powerful productivity tools all within an extendable launcher. Fast, ergonomic and reliable."**
3. After ~1 to 2 seconds, a primary CTA button fades/slides up beneath the subheadline: a white pill button with the grid icon, dynamically labeled by detected OS, e.g. **"Download for Windows"**.
4. Below the button, two lines of small monospace/gray helper text: OS requirement (e.g. "Windows 10+ (x64 or ARM64)") and an alternate install method ("Install via WinGet").
5. Below that, a secondary ghost-style pill button: **"The Raycast Keyboard →"** (links to a merch/keyboard product).

All hero text and buttons are centered, stacked vertically, over the red diagonal background.

## 3. "Take shortcuts, not detours" — Pinned Scroll-Driven Product Demo

This is the site's signature interaction and the most complex section to rebuild. As the user scrolls, a **single mock application window stays pinned/sticky in the viewport** while its internal content changes through several distinct states, synced to scroll position. Below the pinned window, a caption (bold title + gray description) also changes state in sync.

**Section intro copy** (appears first, centered): **"Take shortcuts, not detours."** / **"One interface, everything you need."**

**The mock window itself:**
- Styled like a macOS app frame: a thin top bar showing macOS menu items (`Apple, Finder, File, Edit, View, Go, Window, Help`) and a right-aligned system status bar (icons + "37m left", wifi, battery, clock, date). This establishes it's a native-feeling desktop launcher, not a webpage.
- Below that top chrome sits the actual Raycast command-palette UI: a rounded dark panel with a search input at the top and a results list below, floating centered on the page over a dimmed/blurred version of the previous background.

**State-by-state content inside the pinned window (each state = one scroll "chapter"):**

1. **Clipboard History**: Search input reads placeholder "Type to filter entries...", with an "All Types" dropdown at top right. A two-pane layout: left pane is a scrollable list of clipboard items grouped under "Today" (a copied image entry, color swatches like `#FF6363`, `#59D499`, `#56C2FF`, `#FFC531` each with a colored circular swatch icon, a URL entry, a GitHub link entry, a text snippet, an email). Selecting a color entry shows a right-hand detail pane: a large circular color preview, the hex code, and metadata rows (Application: VS Code, Content Type: Color, Copied: timestamp). Bottom bar shows the current command name ("Clipboard History") on the left and action hints on the right ("Copy to Clipboard ⏎", "Actions ⌘K"). Below the window (in real page flow, still pinned) a small floating icon dock/toolbar of 5 rounded square buttons appears (clipboard, sparkle/AI, emoji, calculator, window-grid), with a tooltip label above the hovered icon. Caption beneath: **"Remember Everything."** bold, followed by gray text **"Stop playing Clipboard ping-pong..."**

2. **AI (Quick AI panel)**: Same window chrome, but content switches to a text input at top ("which note taking apps support markdown?" typed out with a visible blinking-cursor typing animation, character by character) and a response panel below that **streams in progressively** line by line: a numbered markdown list of note apps (Obsidian, Notion, Typora, Bear, Joplin, then more items appear: Zettlr, Boost Note, iA Writer), followed by a "References" row with small numbered source chips (Notion, Obsidian, "+10 more"). The icon dock below highlights the sparkle/AI icon with tooltip "AI". Caption: **"Be Curious."** / gray: "Have a question? Why google it when you can..."

3. **Emoji Picker**: dock highlights the smiley icon, tooltip "Emoji Picker". Caption: **"Express Yourself."** / "Search for emojis and symbols and paste..."

4. **Root Search / Command Palette (default state)**: Input placeholder reverts to "Search for apps and commands...", with "Ask AI" and "Tab" hint chips on the right of the input. Below, a "Suggestions" section lists commands with leading icon, name, source app label, and a right-aligned "Command" tag (Store/Raycast, Clipboard History/Raycast, Search Files/Raycast, My Schedule/Calendar, Define Word/Dictionary), followed by a "Commands" section list (Calculator History, My Schedule, Clipboard History...). Bottom bar: "Open Command ⏎" and "Actions ⌘K". Dock highlights calculator then window-grid icons in sequence, tooltips "Window Management" appear above.

5. **Window Management**: A results list shows window-layout options with small colored rectangle icons representing screen zones (e.g. "Top Left Quarter"), each tagged "Window Management" on the right, "Open Command ⏎ / Actions ⌘K" bar at bottom. Caption: **"Tidy Up."** / "Resize and reorganize your focused window without touching your mouse."

**Interaction notes for the agent:**
- This entire block behaves like a scrollytelling component: the browser scroll position drives which "state" of the mock UI is shown, while the mock window itself does not scroll with the page (it's pinned/`position: sticky` for a fixed scroll distance, then releases).
- Transitions between states are cross-fades, not hard cuts; the previous state's content fades and slightly blurs while the new one fades in.
- Small floating dock icons at the bottom of the window act like a persistent "current mode" indicator; the active icon is lit/white, others are dim gray, and a tooltip pops above whichever one is "active" for that state.
- Captions below the window always follow the pattern: **Bold 2 to 3 word hook.** + normal-weight gray continuation sentence, fading in and out per state.

## Summary of Reusable Interaction Patterns to Implement

1. **Sticky pinned demo window** that swaps internal UI state as the user scrolls through a tall section (Section 3). This is the hardest and most important pattern to replicate faithfully.
2. **Tabbed content swap** where clicking a pill tab both updates the URL hash and cross-fades a card grid below it (Section 5).
3. **Horizontal draggable/auto-scroll carousels** used three times for different content types: brand extension cards, testimonials, and YouTube thumbnails, each with edge-cropping to hint more content, plus optional manual prev/next arrow buttons.
4. **Typing/streaming text animation** for AI demo inputs and outputs, character-by-character for the question, line-by-line/streaming for the answer.
5. **Sequential highlight/reveal animation** on long-form paragraph text, dimming unread text and brightening the "current" sentence (Section 10).
6. **Fade + slide-up entrance** on virtually every headline, subhead, card, and button as it enters the viewport, staggered by a small delay between siblings.
7. **Grain/noise texture** layered over gradient/color backgrounds (hero, Snippets card, Meeting notes card) for a consistent tactile brand texture.
8. **Isometric wireframe illustration style** (blue-line, exploded/stacked 3D) used exclusively in the developer section to visually signal "technical/API" content, contrasted against the flatter, photographic/gradient style used everywhere else.
9. **Consistent card anatomy**: icon/logo top-left, action affordance top-right (chevron/arrow button), bold title, 1 to 2 line gray description, decorative visual filling the remaining card space.
10. **Bold-word-plus-sentence caption pattern** repeated throughout: a short 1 to 3 word bold hook followed by a longer regular-weight gray sentence, almost always structured as `**Hook.** Continuation sentence.`
